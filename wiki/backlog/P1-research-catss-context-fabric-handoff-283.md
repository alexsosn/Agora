The immutable CATSS-TF adapter `3ee63c4c054960b816b14496815815153e5e543d` is registered in Agora as `catss-tf/catss-canonical` after PR #273 merged as `4dd54d892c83925ce94cc7d81beb7e5f173ba48d`. CI [38239047913](https://github.com/alexsosn/Agora/actions/runs/38239047913) performed actual passive fetch, explicit code-execution approval, managed package install, strict network-denied required bubblewrap sandbox, materialization of a synthetic 2-row Genesis .par, provenance check, and standalone Text-Fabric roundtrip (`CATSS_AGORA_STANDALONE_OK`).

**Missing user experience:** this does not show that Context-Fabric can install, discover, prepare, load, query, unload, or remove the generated corpus. The extant Coptic registered materializer job in `.github/workflows/materializer-install.yml` demonstrates all seven MCP operations against a local `tf/` payload after running the producer. Its implementation constructs a `mcp.client.stdio` `ClientSession` with `StdioServerParameters` and invokes `agora_context_fabric.server` under an isolated cache, then calls `install_local_corpus`, `list_available_corpora`, `prepare_corpus` (offline), `load_corpus`, `describe_corpus`, `search`, `unload_corpus`, and `remove_cached_corpus`. The local import is a *separate explicit action*, not a side-effect of the producer registration.

**Crucial CATSS difference:** the native TF warp has `otype.slotType == "alignment"`, not "word". The synthetic fixture creates 2 alignment slots, an LXX-plus flag on slot 2, and a source-derived `catss_alignment_id`. A consumer test must never coercively relabel these as words. Search `alignment` using Text-Fabric query syntax after loading `catss_alignment_id` and `catss_lxx_plus`. If Context-Fabric rejects non-word slot types, capture the real error and fix only the unsupported-generic-slot defect with RED-first regression, rather than falsifying data.

**Scope constraints:** no CCAT files, any external licensed corpus source, or private TF should be committed/downloaded. Use the existing source fixture, registered code-execution approval, and required bubblewrap job; do not bypass sandbox, source validation or the immutable pin. The Agora producer output directory also contains `agora-materialization.json` provenance and TSV sidecars, which the consumer local-import may ignore or preserve; do not assume that their presence is part of native `*.tf` warp. Existing Coptic consumer test is a starting *contract*, not proof that CATSS works.

**Independent risks to test:** proper source identity from local import vs producer receipt, exactly 2 loaded alignment slots and deterministic identifier feature, discoverability, offline preparation without external repo fetch, count query over `alignment`, lifecycle cleanup and no extra source mutation, no success claim if MCP returns `isError`, original CATSS source remains local and unchanged. Parent BHSA/LXX feature-module orchestration is explicitly excluded under #221/#135 and CATSS-TF #16.
