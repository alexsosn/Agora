# Issue #251 — immutable Pseudepigrapha release ZIP introspection gate

## Source research, 2026-10-11
- Pseudepigrapha-TF **v1.0.0** published 2026-09-17: `tf-1.0.zip` 9,632,449 B SHA256 `d2dfad7e643699617a9493b9f5d724868f8027dd5f2e88bd558451e3e7819b7a`; `complete.zip` 9,643,332 B SHA256 `1ea4488202d1e9fbc008abaabff14f220328118fc52bed3a06a2d331b145bb7d`. GitHub release data verified through API; tagged README describes `tf.app.use("alexsosn/Pseudepigrapha-TF")` and offline reload, but these do **not** prove the internal member layout required for Agora's native TF cache.
- Local/container networking cannot access this public release; GitHub-hosted CI can independently fetch immutable bytes. Inspection of the actual ZIP member tree is the missing primary-data research step before a loader design. Do not hallucinate the ZIP's internal root or claim corpus is registered.
- Existing `scripts/agora_materialize.py` has reviewed bounded HTTPS downloader and ZIP member/path/link guards. For this *research-only* gate, reuse its `_download_pinned_archive` digest and HTTPS/redirect policy, then **inspect ZIP central directory only**, without extraction or executing third-party code. Do not confuse this independent probe with a Context-Fabric source resolver.

## Research → plan → preserved RED → GREEN → test
1. **RED**: synthetic ZIP tests for safe nested TF warp `otype.tf` and `oslots.tf` in same root, counts, no directory traversal, no symlink/special entry, member count/expanded-size caps; missing warp or conflicting roots must fail. Bounded download helper is imported from existing covered materializer code.
2. **GREEN**: one pure inspection helper yielding a bounded, structured summary (root candidates, first few member examples, member count/uncompressed bytes), no extraction or dynamic code. A pinned CLI accepts only an internal allowlist of the two v1.0.0 assets, verifies exact digest/bytes, then outputs layout summary.
3. **Real-data gate**: opt-in manually dispatchable and PR-scoped GitHub Actions that downloads exactly the two pinned upstream published assets, confirms each SHA256 and safe member tree, and prints the observed TF root topology. No artifact redistribution and no release archive install; file listing is metadata only.
4. Independently adversarial review the archive parser's duplicate members, symlinks, path normalization, odd zip name encodings and no extraction policy. Exact-head Foundation + live archive probe must pass before merging this **research capability slice**.
5. **Not completion of #251:** implement separate typed archive-backed resource model, bounded transactional extraction and cache/provenance/TF load tests based on the *observed* roots in a later PR. #226 catalog registration remains blocked until full load/query/unload/offline use works.
