# Issue #251 — stage verified TF ZIP features without publishing

## Research evidence, 2026-10-11
- The real published Pseudepigrapha-TF v1.0.0 assets were hash-checked in GitHub Actions `38138542877`: native `tf-1.0.zip` has 96 files, 101,762,166 declared expanded bytes, TF warp at ZIP root; `complete.zip` has 101 files, 101,772,288 expanded bytes, TF warp at `alexsosn/Pseudepigrapha-TF/tf/1.0`. They have different roots; no guessed subpath may be used.
- The existing `scripts/probe_tf_release_asset.py` validates archive identity and central-directory safety without extraction, but is **not part of the Context-Fabric plugin runtime**. The runtime already owns `LocalImports._files`, `LocalImports.install()` data-only feature checks, source race detection, SHA256 per feature, atomic cache publication and an evictable local receipt.
- `LocalImports.install()` assigns random `local-<uuid>` resource IDs and **cannot** by itself provide stable registered release identity. `ContextFabricResolver.prepare` currently branches on Git-repository, collection and user-local sources; no archive-backed registered source branch yet.

## Bounded RED → GREEN milestone
1. **RED:** synthetic archive fixtures exercise flat native TF root and nested stock Text-Fabric root; validate SHA256 before any extraction, portable TF feature names, required three warp/config files, member/byte caps, duplicate/casefold names, hostile traversal/drive/symlink/special entries, malformed UTF-8, missing headers and cleanup on failure. Test stage exists only within `with` context and is removed on exit.
2. **GREEN:** plugin-owned `release_archive.py` exports `staged_verified_tf_zip(path, *, expected_sha256, ...)` context manager that verifies the compressed checksum in bounded chunks, scans ZIP central directory, finds *exactly one* paired warp root (not guessed from filename), safely streams only portable `.tf` files into a temporary staging tree, validates TF UTF-8/headers and leaves **all publication to the existing trusted local-import/cache owner**. No direct destination path, no network, no loose fallback or update to registry strategy.
3. Reuse public code only after explicit sandbox trust boundary: source bytes from the pinned release probe, but plugin runtime must not import Agora's repository-local `scripts` module. Stage is a reusable pure-data step that will be integrated into a typed `github-release-archive` resolver later.
4. Independent adversarial review of ZIP central-directory aliases, duplicate casefolds, ZIP-bomb bounds, source digest-before-extract, failure cleanup, and no publication. Run local unit tests and exact-head Foundation/Context-Fabric audit; do **not merge** until green.
5. **Non-goals:** downloader and HTTP redirects (still #251), stable registered resource identity, immutable cache receipt/provenance, load/query/unload/offline restart, corpus metadata/license attestation. Issue #251 and #226 remain OPEN after this milestone.
