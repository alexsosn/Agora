# #251 — durable immutable TF release snapshot, without corpus registry changes

## Grounded research, 2026-10-11
- PRs #255 and #256 are merged: real Pseudepigrapha-TF v1.0.0 `tf-1.0.zip` is SHA256 `d2dfad7e643699617a9493b9f5d724868f8027dd5f2e88bd558451e3e7819b7a`, 96 verified native TF features / 101,762,166 bytes under a flat ZIP root. `complete.zip` carries the same 96 feature files under a nested root. `staged_verified_tf_zip` is a data-only, checksummed, bounded temporary extraction helper and **does not** publish persistent cache data.
- Current `GitStore._cache_identity` recognizes only exact `snapshots/<resource-key>/<revision>/corpora/__root__` (or feature-modules) as separately leaseable/evictable cache objects; `touch_cache_object`, `acquire_cache_lease`, cache prune and `_cleanup_empty_parents` own their lifecycle.
- Current `LocalImports.install` is a proven data-only feature validator and receipt/copy primitive, but creates random `local-<uuid>` IDs incompatible with canonical, stable registry identity. It also uses a receipt for payload and descriptor integrity, and re-verifies feature bytes before preparing. Do not spoof local IDs to satisfy registered release discovery.
- Current `ContextFabricResolver.prepare` and static schema only support repository/collection/local-module (plus dynamic user-local). No release-backed registered path or pinned remote asset fetch can be advertised without a later tested implementation.

## Research → RED → GREEN milestone
1. RED tests with a **real GitStore configured for a tiny temp cache** and native TF ZIP fixture demand: checksum-verified staging; deterministic snapshot `snapshots/<stable-resource>/<asset-sha256>/corpora/__root__` and receipt with immutable source tag/digest, version and individual SHA256 feature manifest; same artifact repeated is idempotent; offline open/prepare after a new process; byte corruption fails before returning a usable `PreparedCorpus`; source change/revision collisions fail closed; published path must be usable under an existing shared cache-object lease and removable through normal cache prune; short/invalid TF input, symlinks, illegal resource IDs and malicious ZIP do not leak temporary/indexed snapshots.
2. GREEN plugin-owned `release_snapshots.py` imports `staged_verified_tf_zip` and `LocalImports._files`, writes a signed-by-content (not cryptographically authenticated) internal receipt, atomically renames fully validated features under cache transition lock and calls `GitStore.touch_cache_object` only **after** receipt publication. Reopening validates full feature hashes, enforces exact source digest, version/repository/tag bindings and returns canonical-ID `PreparedCorpus`.
3. No HTTP download, no untrusted materializer execution, no corpus registry row or schema new value, no automatic load/prepare on behalf of a user. This is an internal trusted primitive, **not yet usable as a registered release loader**. Stable snapshot provenance originates in trusted catalog pin passed by the future caller; local receipt does not authenticate upstream on its own.
4. Exact-head CI: Foundation (real repository/catalog tests), materializer/Context-Fabric local-import smoke if triggered, and separate adversarial review of TOCTOU, per-file verification, atomic rollback, cache eviction leases and source pin. Any new live workflow must keep actual pinned Pseudepigrapha archive checks; cannot claim full load/query/unload until a later PR implements resolver integration.
5. Keep #251 and #226 OPEN for typed archive strategy, acquisition policy/source-mode controls, real fresh-cache load/query/unload and offline reloading under stable catalog ID, provenance/rights presentation, and security acceptance.
