# Issue #246 — risk-based CI gates and documentation-only fast path

## Real source and run evidence, 2026-10-11
- `.github/workflows/foundation.yml` runs on **every pull_request** without a path gate. It always schedules seven jobs: one Ubuntu `Repository foundation, registry, and manifests` plus **three OS-specific Context-Fabric cache lifecycle and three OS-specific materializer install-lock jobs**, even for Markdown-only changes.
- Its foundation job runs `python -m compileall`, full canonical registry and three generator freshness checks, then `python -m unittest discover -s tests -v`. Example: PR #244 Foundation run `38126354654` spent 373.784s running 986 tests and revealed one stale inline-doc assertion, not a runtime regression. PRs #243, #244, #245 and #247 reran the same broad suite after docs changes.
- `.github/workflows/external-mcp-smoke.yml` watches `README.md`, `wiki/guides/installation.md`, and `wiki/guides/compatibility.md` as well as runtime/registry manifests; it runs 14 representative/startup matrix checks on their changes. This is not automatically wrong for *new compatibility claims*, but is overly broad for heading or troubleshooting-link edits.
- `CONTRIBUTING.md` explicitly calls for proportional document-only validation, lighter doc/link/generator checks, and full runtime evidence for runtime/cache/installer/integrity changes.
- Branch protection/required job status policy must be inspected before skipping any existing job. Preserve the stable 'Repository foundation, registry, and manifests' check name; fail closed on any unrecognized/ambiguous/mixed path.

## Plan and gates
1. **Research/RED:** write pure, deterministic changed-path selection tests with paths from real PRs #243 (docs+research+doc generators), #244 (docs+tests+generator), #245 (four tutorials+generator), #247 (docs integrity), and negative cases for `.github/`, `registry/`, `plugins/`, runtime scripts, pinned dependencies, caches, materializers, and any mixed change. A missing/empty/absolute/traversal/non-POSIX path must force full checks.
2. **GREEN:** implement a small classifier script returning docs-only vs full with a strict allowlist; keep hard defaults full for unknown files and explicit runtime-affecting patterns. Give the CLI a safe `git diff -z` path parser in an optional follow-up, never directly interpolate PR-controlled paths into shell.
3. **Workflow integration:** only after branch-protection and unit-test review, add a scope job (PR vs main push), keep main Foundation job name stable and ensure docs-only path executes generated artifact checks and curated user docs/research/registry truthfulness tests. Skip cross-platform cache/install matrix **only for classified doc-only PRs**. Keep full runtime tests on pushes to main and for any mixed/unrecognized PR. Determine whether external MCP smoke should use a separate claim-change gate rather than blindly disabling it.
4. Independently adversarial review from a mixed malicious change: ensure adding a harmless Markdown file cannot mask modifications to runtime code, config, dependencies, or workflow. Test stale generated docs, inaccurate capability claims and rejected alias paths. Run exact-head Foundation, affected smoke gates and PR merged behavior before declaring CI saved.
5. Benchmark actual runner minutes and elapsed time after implementation. Do not claim savings without a representative successful sample.

This is a high-risk CI-selection change: selection errors could conceal bugs. Do not merge a classifier-only PR as if it had already reduced CI; workflow integration and required-status semantics must be proven separately.

## Adversarial findings and delivered scope

- Attempting to inspect legacy branch protection with the available integration returns **HTTP 403**; repository rulesets are empty but this is insufficient to prove required-check behavior. Thus **do not skip, rename, or conditionally disable any check in this PR**.
- The first classifier treated documentation generators and test modules as docs-only. Independent code-boundary review found that they execute Python and can change control flow; preserved a new RED case `test_adversarial_python_changes_never_qualify_for_docs_only` and corrected the classifier to accept **plain Markdown only**. As a result, the real historical PRs with generator/tests correctly classify **full**; this is intentional fail-closed behavior, not a runtime savings claim.
- Added a NUL-delimited Git raw diff parser with explicit regular-file modes (100644 only), exact A/M/D status transitions, no rename inference, and rejection of symlinks, executable mode changes, unknown paths, malformed bytes, and shallow/nonmerge checkouts. Verified native `git diff --raw -z --abbrev=40` layout separately against actual temporary Git commits.
- The Foundation workflow now emits an **informational, non-gating** scope diagnostic on pull requests after setup-python; `continue-on-error: true` and unchanged seven jobs preserve all existing validations, with two-commit checkout depth to inspect the PR merge first parent. This is data collection only.
- A future separate change may use the diagnostic for actual CI selection **only after** required-status inspection and trusted, base-branch-owned classification are designed and tested. Never let untrusted PR-modified executable code decide which required checks to skip.
