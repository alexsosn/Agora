Independent review of the isolated PR found six concrete defects. Valid Text-Fabric feature names containing `@` were rejected. The advertised content revision also depended on random/descriptive receipt metadata. A malformed local receipt could break the whole merged catalog and prevent targeted removal; the follow-up review also checked a structurally malformed but hash-consistent descriptor rather than only truncated JSON. Failure while indexing the cache after the atomic directory rename left a receipt-discoverable but unevictable local resource. A later lifecycle pass also found that parent-cascade removal deleted the parent before dependent modules: if a dependent module was leased or transition-blocked, the dependency edge disappeared and retrying by parent ID could falsely succeed while leaving an orphaned module. The same review exposed a publication/removal race: a local module could validate its generated parent, wait behind removal, then publish after the parent disappeared. Preserved RED regressions were added before each corresponding fix. The implementation now accepts established TF `@` feature names, derives `source_revision` only from the canonical feature manifest, protects receipt metadata with a separate integrity hash, validates persisted descriptors before catalog admission, skips invalid receipts with a diagnostic, permits targeted removal by a generated local resource ID even when its receipt is unreadable, rolls back the published snapshot plus cache sidecars when cache indexing fails, removes dependent modules before their local parent while keeping the parent intact on any partial cascade failure so the operation remains retryable, revalidates generated parent identity inside the module-publication transition, and holds the exclusive cache transition from dependency rescan through atomic detachment.
