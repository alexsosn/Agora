# Plugins

This directory contains Agora plugin integrations.

Each v0.1 plugin root carries generated native metadata and MCP launch configuration for Claude Code and ChatGPT/Codex:

```text
plugins/<id>/
├── .claude-plugin/
│   ├── plugin.json
│   └── mcp.json
├── .codex-plugin/
│   ├── plugin.json
│   └── mcp.json
└── skills/
    └── <skill-name>/
        └── SKILL.md
```

The native manifests and MCP configuration files are generated by `scripts/generate_marketplaces.py` from the canonical registry plus the runtime adapters in the generator. Do not hand-edit generated metadata; change the registry/generator and regenerate instead.

## Scholarly skills

Agora skills follow the portable Agent Skills directory convention: one skill directory containing a `SKILL.md` with YAML frontmatter and research instructions. They are deliberately kept client-neutral unless a supported client requires an adapter.

The initial v0.1 skill layer includes:

- **Context-Fabric:** provider workflow, BHSA/ETCBC, CUC/Ugaritic, TLHdig-TF/Hittite, and heterogeneous Greek collection guidance;
- **Perseus:** CTS/Scaife discovery, URNs, passage retrieval, and form/lemma search;
- **Sefaria:** references, source/translation layers, search, links, dictionaries, and manuscripts;
- **SEDRA:** Syriac word-form versus lexeme lookup and ambiguity handling.

`tests/test_skills.py` validates required skills, frontmatter, size limits, real tool references, and source-specific research invariants.

## Upstream-first rule

Third-party MCP implementations should normally be referenced and versioned rather than vendored. Agora should contain local runtime code only when adaptation is genuinely required, as with the SEDRA adapter and Context-Fabric resource layer.

Plugin-level verification and underlying resource/data verification remain separate claims.
