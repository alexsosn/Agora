# Plugins

This directory contains **thin Agora integrations** for third-party scholarly plugins and services.

Each v0.1 plugin root carries generated native metadata and MCP launch configuration for Claude Code and ChatGPT/Codex:

```text
plugins/<id>/
├── .claude-plugin/
│   ├── plugin.json
│   └── mcp.json
├── .codex-plugin/
│   ├── plugin.json
│   └── mcp.json
└── skills/
    └── <skill-name>/
        ├── SKILL.md
        └── agents/
            └── openai.yaml
```

The native manifests and MCP configuration files are generated by `scripts/generate_marketplaces.py` from the canonical registry plus the runtime adapters in the generator. Do not hand-edit generated metadata; change the registry/generator and regenerate instead.

## Thin-integration rule

Agora owns discovery, metadata, installation, launch, transport/configuration adaptation, resource selection, and integration verification. It does **not** own the domain semantics or missing features of third-party plugins.

If the same bug or missing capability appears when the upstream plugin is run without Agora, fix/report it upstream. Agora may document the limitation, constrain a version, or adjust verification metadata; it should not monkey-patch the plugin, replace its algorithm, or add the missing scholarly capability locally.

See [`../wiki/architecture/ref-plugin-boundary.md`](../wiki/architecture/ref-plugin-boundary.md) for the normative policy.

## Skills

Substantive domain skills for a third-party plugin should live with that plugin upstream whenever practical.

Skills committed under an Agora plugin wrapper are limited to **facilitation of capabilities the upstream plugin already exposes**: identifier/resource discovery, selecting among existing tools, configuration, limitations, interpretation cautions, provenance, and reproducibility guidance.

They must not emulate missing upstream tools, repair incorrect upstream results, or introduce a new domain algorithm.

Generic cross-plugin marketplace skills and repository-maintenance skills are Agora-owned and may live outside individual plugin packages. Repository-maintenance skills for coding agents live under `.agents/skills/`.

The behavioral source for a packaged plugin skill remains `SKILL.md`. Client-specific UI metadata must not duplicate or override its instructions.

The initial v0.1 facilitation layer includes:

- **Context-Fabric:** provider/resource workflow and guidance for registered corpora/collections;
- **Perseus:** CTS/Scaife discovery, URNs, passage retrieval, and use of published search tools;
- **Sefaria:** references, source/translation layers, search, links, dictionaries, and manuscripts;
- **SEDRA:** Syriac word-form versus lexeme lookup and ambiguity handling.

`tests/test_skills.py` validates packaged plugin skills, Agent Skills frontmatter, size limits, real tool references, source-specific research invariants, and Codex UI metadata.

## Testing boundary

Plugin tests should verify Agora-owned integration contracts: generated configuration, launch/transport, advertised tool discovery, Agora-owned resource resolution, and smoke-level access to representative published upstream operations.

Do not reproduce third-party semantic test suites in Agora. Search correctness, parser correctness, exact counts, linguistic analyses, ranking, and other upstream algorithms belong upstream unless Agora itself introduced the defect.

Plugin-level verification and underlying resource/data verification remain separate claims.
